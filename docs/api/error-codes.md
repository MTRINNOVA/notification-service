# Catálogo de códigos de error — v1

**Estado:** aprobado (PD-04 y PD-08, 2026-11-15). Es la lista **cerrada** de valores de `code` en las respuestas RFC 9457. Añadir un código requiere justificar su uso, actualizar este catálogo y [openapi.yaml](openapi.yaml), y revisar el contrato.

## Formato

Todas las respuestas de error usan `application/problem+json` ([RFC 9457](https://www.rfc-editor.org/rfc/rfc9457)):

| Campo      | Obligatorio    | Contenido                                                                                                                                                                                                          |
| ---------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `type`     | Sí             | URI del tipo de problema: `{PROBLEM_TYPE_BASE_URI}/{code-en-kebab-case}` (p.ej. `.../whatsapp-daily-quota-exceeded`). La base URI se fijará con el DNS definitivo (PD-06); hasta entonces, `about:blank` es válido |
| `title`    | Sí             | Resumen estable y legible del tipo de problema                                                                                                                                                                     |
| `status`   | Sí             | Código HTTP                                                                                                                                                                                                        |
| `detail`   | Sí             | Explicación de esta ocurrencia, sin datos internos ni secretos                                                                                                                                                     |
| `instance` | Sí             | Ruta de la solicitud                                                                                                                                                                                               |
| `code`     | Sí             | Código estable de este catálogo. **Los clientes deben decidir según `code`, no según `title` ni `detail`**                                                                                                         |
| `traceId`  | Sí             | Identificador de traza para soporte                                                                                                                                                                                |
| `errors`   | Solo si aplica | Errores por campo (`400`): `{ "campo": ["mensaje", ...] }`                                                                                                                                                         |
| `retryAt`  | Solo si aplica | Instante UTC en que se puede reintentar (`429`); acompaña a la cabecera `Retry-After`                                                                                                                              |

## Semántica de códigos HTTP

| HTTP  | Uso                                                                                                                                              | Ejemplo                                 |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------- |
| `400` | Formato, sintaxis o estructura inválidos: JSON mal formado, campo requerido ausente, tipo/longitud/enum incorrecto, cabecera obligatoria ausente | Falta `Idempotency-Key`                 |
| `401` | Autenticación ausente o inválida                                                                                                                 | API Key revocada                        |
| `403` | Autenticado sin permiso para la operación                                                                                                        | `viewer` intenta cancelar               |
| `404` | Recurso inexistente **o fuera del ámbito visible** del principal (no se revela la existencia de recursos de otro tenant)                         | `notificationId` de otra organización   |
| `409` | Conflicto con el estado actual del recurso o de idempotencia                                                                                     | Cancelar una notificación ya despachada |
| `413` | Cuerpo o archivo demasiado grande                                                                                                                | Adjunto por encima del límite           |
| `415` | Tipo de contenido no soportado                                                                                                                   | Adjunto con MIME no permitido           |
| `422` | Solicitud bien formada que incumple una regla de negocio                                                                                         | Sin remitente predeterminado            |
| `429` | Cuota o rate limit excedido; incluir `Retry-After` cuando sea calculable                                                                         | Cuota diaria de WhatsApp                |
| `500` | Error inesperado (puede ocurrir en cualquier operación; no se declara en cada una)                                                               | Excepción no controlada                 |
| `503` | Dependencia temporalmente no disponible                                                                                                          | Evolution no responde al obtener el QR  |

## Catálogo

| `PERMISSION_DENIED`                            | 403  | Permiso, rol o scope insuficiente                                                                                                                                                                                                                     | Necesario para que todo `403` tenga `code` ([rbac-matrix.md](../security/rbac-matrix.md))                                       |

| `NOTIFICATION_ALREADY_DISPATCHED`              | 409  | Cancelar una notificación cuya entrega ya salió hacia el proveedor                                                                                                                                                                                    | PD-04; [api-design.md](api-design.md) (cancelar "si aún no se despachó")                                                        |

| `DEFAULT_SENDER_NOT_CONFIGURED`                | 422  | Se omitió `senderId` y la aplicación no tiene remitente predeterminado válido                                                                                                                                                                         | PD-04; [DECISIONS-v1.5.md](../project/DECISIONS-v1.5.md) §3                                                                     |

| `APPLICATION_LIMIT_EXCEEDS_ORGANIZATION_LIMIT` | 422  | Se intenta fijar un límite de aplicación mayor que el efectivo de la organización                                                                                                                                                                     | criteria §5; erd `application_limits`                                                                                           |
| `ROLE_NOT_ASSIGNABLE`                          | 422  | Se intenta asignar en una membresía `super_admin` o un código que no está en el catálogo (`organization_admin`, `operator`, `viewer`)                                                                                                                 | PD-01, TP-20                                                                                                                    |
| `ATTACHMENT_NOT_AVAILABLE`                     | 422  | Un `attachmentId` de la misma aplicación está eliminado, expirado o bloqueado por el escaneo                                                                                                                                                          | TP-18                                                                                                                           |
| `LAST_SUPER_ADMIN_REVOCATION_FORBIDDEN`        | 422  | Se intenta revocar la última asignación activa de `super_admin`                                                                                                                                                                                       | TP-15                                                                                                                           |
| `PROVIDER_DIAGNOSTICS_NOT_SUPPORTED`           | 422  | El proveedor de la cuenta no admite la prueba de conexión o la consulta de salud                                                                                                                                                                      | TP-17                                                                                                                           |
| `WHATSAPP_DAILY_QUOTA_EXCEEDED`                | 429  | Cuota diaria agregada de WhatsApp de la organización alcanzada                                                                                                                                                                                        | PD-04; DECISIONS §8                                                                                                             |

En el diagnóstico de cuentas, la indisponibilidad del proveedor se informa en el resultado (`200`)                                                   | PD-04, TP-17                                                                                                                    |
| `SERVICE_TEMPORARILY_UNAVAILABLE`              | 503  | Una dependencia interna (PostgreSQL, RabbitMQ, Redis, MinIO) no está disponible                                                                                                                                                                       | Definición de `503` en api-design                                                                                               |

## Reglas

- `code` es estable: no se renombra ni se reutiliza con otro significado.
- `detail` nunca incluye secretos, tokens, payloads de proveedor, stack traces ni datos de otro tenant.
- Una petición idempotente repetida con el **mismo** cuerpo no es un error: devuelve el recurso original.
- Un webhook duplicado no es un error: se responde con éxito y se deduplica.
